# Kosli Provider

The Kosli provider allows you to manage Kosli resources as Infrastructure-as-Code using Terraform. Use it to define and manage custom attestation types and integrate Kosli into your compliance workflows.

## Example Usage

```terraform
terraform {
  required_providers {
    kosli = {
      source = "kosli-dev/kosli"
    }
  }
}

# Configure the Kosli Provider
# Authentication via environment variables (recommended)
provider "kosli" {
  # API token - set via KOSLI_API_TOKEN environment variable
  # api_token = "XXXXX"

  # Organisation name - set via KOSLI_ORG environment variable
  # org = "Organisation"

  # Optional: API endpoint URL (defaults to https://app.kosli.com)
  # api_url = "https://app.us.kosli.com"  # Use US region

  # Optional: HTTP client timeout in seconds (defaults to 30)
  # timeout = 60
}
```

## Authentication

The provider requires a Kosli API token and organization name for authentication. These can be configured in two ways (in order of precedence):

1. **Provider configuration** - Set directly in your Terraform configuration
2. **Environment variables** - Use `KOSLI_API_TOKEN` and `KOSLI_ORG`

### Creating an API Token

To create an API token:

1. Log in to [Kosli](https://app.kosli.com)
2. Navigate to **Settings** → **API Tokens**
3. Click **Create Token**
4. Copy the token and store it securely

~> **Warning:** API tokens grant full access to your Kosli organization. Store them securely and never commit them to version control.

### Required Permissions

Use a token that belongs to a user or service account with the **Admin** role.

Some operations the provider performs are restricted to admins. In particular, destroying a `kosli_environment` or `kosli_logical_environment` archives the environment in Kosli, and archiving requires the Admin role. With a Member token, `terraform apply` can create and update environments, but `terraform destroy` (or removing the resource from your configuration) fails with `403 Forbidden` and the resource stays in state.

The recommended setup is a dedicated service account with the `admin` privilege and an API key minted for it. You can create both with this provider using the `kosli_service_account` and `kosli_service_account_api_key` resources (this initial bootstrap must itself run with an Admin token, since a service account cannot be granted a higher privilege than the caller's), or in the Kosli UI under **Settings** → **Service Accounts**.

## Regional Endpoints

Kosli operates in multiple regions. Configure the `api_url` to match your organization's region:

- **EU (Default)**: `https://app.kosli.com`
- **US**: `https://app.us.kosli.com`

## Telemetry

Alongside the `User-Agent`, every request the provider sends to Kosli carries these headers, which Kosli uses to understand how the provider is used:

- `X-Kosli-Client`: the provider name and version, for example `terraform/v0.11.0`
- `X-Kosli-Operation`: the resource, data source or list resource type and the operation, for example `kosli_environment create` or `data.kosli_flow read`
- `X-Kosli-Invocation-Id`: a random ID generated each time Terraform starts the provider, which groups the requests from that run

They contain only type names and operation names. No configuration values, such as resource names, URLs or IDs, are sent in these headers.
